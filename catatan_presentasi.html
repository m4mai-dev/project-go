Sistem Backend REST API Rental Barang (Golang + MySQL)

1

Pembukaan & Problem Statement (Latar Belakang)

Durasi: ~2 Menit
🗣️ Script Bicara Anda:

"Selamat pagi/siang Bapak/Ibu penguji. Hari ini saya mempresentasikan proyek backend service: Sistem Rental Barang Berbasis RESTful API menggunakan Golang.

Pada bisnis rental barang (seperti alat kamera, audio podcast, maupun perlengkapan kantor), tantangannya berbeda dengan e-commerce biasa. Sistem tidak hanya mencatat kuantitas stok, tetapi harus mampu melacak identitas setiap unit fisik secara presisi melalui nomor seri aset, menghitung durasi sewa, mengelola status ketersediaan, mendeteksi denda keterlambatan pengembalian, serta mencatat verifikasi bukti pembayaran."

💡 Poin Tekanan: Jangan sebut ini sekadar toko online. Tekankan konsep "Asset Unit Tracking" & "Rental Lifecycle".
🎯 Solusi: REST API modular dengan integritas transaksi ACID pada MySQL dan autentikasi token JWT.
2

Arsitektur & Pilihan Teknologi (Tech Stack)

Durasi: ~3 Menit
1. Golang (Go)
net/http Standard Library

Kompilasi native biner tunggal tanpa dependency runtime berat, efisiensi memori luar biasa, serta model concurrency goroutines.

2. MySQL & Engine InnoDB
Relational & ACID Compliant

Menjamin transaksi perbankan & booking tidak korup menggunakan BEGIN, COMMIT, dan ROLLBACK.

3. JWT & Bcrypt
Stateless Security

Autentikasi stateless hemat bandwidth dengan masa berlaku token 24 jam, serta hashing password menggunakan salt acak.

🗣️ Script Bicara:

"Kami sengaja memilih pustaka standar net/http bawaan Go untuk membuktikan pemahaman fundamental backend yang kokoh tanpa bergantung secara berlebihan pada framework pihak ketiga."

3

Desain Basis Data (ERD Normalization)

Durasi: ~3 Menit
category (1) → (N) products (1) → (N) item_instances (1) → (N) rentals (1) → (N) payments ↑ (N) ← (1) user
⚡ SENJATA RAHASIA JAWABAN DOSEN: "Kenapa memisahkan Products dan Item Instances?"

Jawaban Anda: "Jika kita hanya menyimpan kuantitas stok angka di tabel produk, kita tidak bisa mengetahui secara spesifik unit fisik bernomor seri berapa yang sedang dibawa pelanggan A, unit mana yang sedang diservis teknisi, dan unit mana yang kondisinya prima. Dengan tabel item_instances, setiap unit fisik memiliki identitas unik (asset_code) dan riwayat siklus hidup tersendiri."

4

Alur Bisnis & Use Case Diagram

Durasi: ~3 Menit
Flow Pengguna (Customer)
  1. Registrasi & Login sistem untuk memperoleh token JWT.
  2. Eksplorasi katalog produk & melihat ketersediaan unit.
  3. Menentukan durasi sewa (tanggal mulai s/d tanggal kembali).
  4. Submit order rental barang & alamat pengiriman.
  5. Melakukan pembayaran & mengunggah bukti transfer.
  6. Mengembalikan barang setelah masa sewa selesai.
Flow Pengelola (Admin)
  1. Login sebagai administrator.
  2. CRUD data kategori, produk, dan unit fisik barang.
  3. Melihat daftar pesanan rental yang baru masuk.
  4. Memvalidasi bukti pembayaran dan menyetujui pesanan.
  5. Memvalidasi pengembalian barang & kalkulasi denda jika terlambat.
  6. Melihat rekapitulasi penjualan & performa sewa.

Kisi-Kisi Pertanyaan Kritis Penguji & Jawaban Taktis

Anti-Gugup Cheatsheet
T: "Bagaimana cara Anda mencegah terjadinya penyewaan ganda (double-booking)?"

J: "Kami menerapkan pengecekan status unit langsung pada level query transaksi basis data. Ketika pesanan baru diproses, sistem memastikan status unit di tabel item_instances adalah available, dan secara atomik mengupdatenya menjadi rented dalam satu transaksi."

T: "Kenapa memilih arsitektur REST API ketimbang Monolith dengan HTML template server-side?"

J: "Dengan arsitektur REST API murni, backend menjadi client-agnostic (tidak terikat antarmuka tertentu). Endpoint yang sama dapat dikonsumsi oleh aplikasi Web modern (React/Next.js), Mobile App (Flutter/Android), hingga mesin kasir POS internal tanpa perlu merombak ulang logic backend."

T: "Apa fungsi Transaction (Begin, Commit, Rollback) pada fungsi hapus produk?"

J: "Untuk menjamin integritas data (ACID). Saat menghapus produk, unit-unit fisik anak di item_instances juga harus ikut dihapus. Jika terjadi kegagalan sistem saat menghapus produk setelah unit terhapus, maka perintah tx.Rollback() akan membatalkan seluruh perubahan agar database tidak meninggalkan data sampah atau data cacat."
